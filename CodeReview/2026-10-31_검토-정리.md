## Claude 원문을 읽을 때 보정할 부분

원문을 다시 코드와 대조한 결과다. 아래 메모는 Codex가 작성했으며 Claude의 추가 응답이 아니다.

- **N04의 반박 대상이 없다.** Codex 원문은 0:0:0일 때 칼만 나온다고 주장하지 않았다. 별도 정책이 필요하다고만 썼다. 현재 0:0:0은 런처로 폴백한다는 Claude의 코드 해석 자체는 맞다.
- **N06의 정상 상태 처리량 계산:** 빈 큐의 첫 4발이 나가는 시간은 0.36초지만, 연속 요청을 붙일 때 `Last().LaunchTime + Spacing`을 사용한다(`CRWeaponComponent.cpp:968`). 따라서 요청당 4개의 발사 슬롯은 **0.48초**를 소비한다. 강화 간격 1.024초에서 누적 기준은 공격속도 **약 +113.3% 초과**다. Claude 원문의 약 +184%는 최초 묶음의 0.36초만 사용한 계산이다. 원 리뷰의 +500% 재현 조건에는 영향이 없다.
- **N02의 죽은 시체 반납:** HP가 0인 동안 추가 피해가 막힌다는 지적은 맞다. 그러나 재획득 후 `RestoreFullHealth()`가 호출되고 아직 화상 시간이 남아 있으면 다음 생명에 피해가 이어지는 원 리뷰 경로는 유효하다. 살아 있는 몬스터의 조기 반납은 풀 내부 피해·골드 드랍까지 확인하기 좋은 별도 재현이다.
- **A01의 기본값 재현은 확정하지 않는다.** 기본 `MissileCount=1`은 `ShootMissiles()` 안에서 즉시 발사되어 큐가 비고, 기본 사체 반납 시간은 1.5초다. 원문의 "발사 직후 사망"만으로 잔여 큐를 보장할 수 없다. 공용 `MissileCount`를 4 이상으로 두고 웨이브 런처가 묶음 발사 중일 때 `CRWave stop`을 실행하는 식으로 잔여 큐 조건을 만들어 검증한다. 몬스터가 플레이어 업그레이드를 자동으로 상속한다는 경로도 확인되지 않았다.
- **A02는 중첩 정책 결정이 필요하다.** 코드 주석은 화상을 겹치지 않고 갱신한다고 명시한다(`CRCombat.cpp:229`). 공격자별 중첩이 요구사항인지 합의되지 않았으므로, 다른 공격자의 화상을 지운다는 사실만으로 독립 결함을 확정하지 않는다. 여러 공격자의 반복 갱신이 N03을 악화시키는 것은 별개다.
- **A03은 현재 기능 결함으로 집계하지 않는다.** 프리셋이 2개인 현재는 탭 선택이 맞게 동작한다. 3개 이상으로 늘릴 때 바꿀 코드라는 예방적 지적이다.
- **A04는 잘못된 JSON 입력에 대한 보강 후보다.** 현재 투구 데이터의 중복 때문에 발생한 실제 문제는 확인하지 않았다. 업그레이드 ID 중복 검사는 별도로 통과했다.
- **N03의 +20% 경계:** 간격과 주기가 정확히 0.5초로 같으면 타이머/입력 처리 순서에 따라 결과가 달라질 수 있다. 안정적인 재현은 원 리뷰처럼 **+50%**를 사용한다.
