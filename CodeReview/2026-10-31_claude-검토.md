### N06 — 패시브 런처 큐 무제한 append · **부분 동의 / P2** (회귀 맞음, 추가 파생 결함은 A01로 분리)

**회귀임을 확인한 근거** — `review-diff.patch:7514-7518` (삭제된 옛 코드)
```
-	PendingMissiles = FMath::Max(Count, 1);
-	MissileSalvoSize = PendingMissiles;
-	MissileSalvoIndex = 0;
-	MissileSpacing = 0.05f * (bSuper ? SuperMissileSpacingScale : 1.f);
-	NextMissileTime = WeaponClock;
```
옛 구현은 새 요청이 **대기열을 덮어썼다** → 큐 길이 ≤ `Count`로 자동 상한. 새 구현(`CRWeaponComponent.cpp:968`)은
```cpp
const float FirstLaunch = PendingMissiles.Num() > 0 ? FMath::Max(PendingMissiles.Last().LaunchTime + Spacing, WeaponClock) : WeaponClock;
```
로 **마지막 발 뒤에 붙인다**. 상한도, 장비 해제 시 취소도 없다(`PendingMissiles`는 전 소스에서 `ShootMissiles`/`UpdateMissileQueue` 두 곳에서만 쓰이며 어디서도 `Reset()` 되지 않음 — grep으로 확인).

**숫자 검증 (손계산)**
- 패시브 런처 기본 `Interval` = 2.0초 (`weapons.json:16`)
- `plauncher_rate` 3단계 → `2.0 × 0.8³ = 1.024초`
- `plauncher_count` 3단계 → `Count = 1 + 3 = 4발`, `SingleSpacing = 0.12` (`CRWeaponComponent.cpp:58`) → 처리에 `0.36초`
- 즉 **기본 공격속도(0%)에서는 1.024 > 0.36이라 누적되지 않는다.** Codex도 "기본 설정만으로 무한 증가한다고 주장하는 항목은 아니다"라고 정확히 선을 그었다.
- 누적 시작점: `1.024 / (1 + AS/100) < 0.36` → **AS > 약 184%**. `PlayerAttackSpeed` 슬라이더 상한은 500% (`CRTuningSettings.cpp:488`)이므로 **옵션창만으로 도달 가능**하다. AS 500%에서는 요청 주기 0.171초 vs 처리 0.36초 → 적이 계속 있는 동안 큐가 선형 증가하고, 패시브를 빼도 밀린 발사가 계속 나간다.

**결론**: "무제한 append + 상한/취소 없음"은 사실이고 설계상 결함이 맞다. 다만 **기본 설정에서는 재현되지 않으며**, 트리거는 극단 튜닝이다. 우선순위는 P2로 유지하되, 같은 코드가 만드는 더 심각한 문제는 아래 **A01**이다.

**최소 수정**
```cpp
// ShootMissiles() 안, PendingMissiles에 넣기 전
constexpr int32 MaxPendingMissiles = 24;
if (PendingMissiles.Num() >= MaxPendingMissiles) { return; }   // 또는 Count를 남은 자리만큼 줄임
```
그리고 취소 지점을 명시한다:
- `UCRWeaponComponent::Equip()` — 런처에서 다른 무기로 **바뀔 때만**(`bChanged`) `PendingMissiles.Reset()`
- `ACRCharacter::OnPoolReleased()` / `Die()` — `WeaponComponent->CancelPendingMissiles()` 호출 (A01과 함께 해결됨)

**회귀 검증**: `cr.Tune PlayerAttackSpeed 500`, 패시브 런처 + `plauncher_count`/`plauncher_rate` 최대, 적을 계속 붙여 두고 30초. `PendingMissiles.Num()`이 상한 안에 머무는지. 그 뒤 패시브 칸을 비우면 잔여 발사가 즉시 멈추는지. 필살기 일제 사격(`CRWeaponAbilities.cpp:195`, `SuperMissileCount`)이 상한에 잘려 짧아지지 않는지 — 상한값은 `SuperMissileCount` 최대치보다 커야 한다.

## 6. 미완료 / 후속 필요

1. **빌드 미확인** — 위 수정안은 전부 정적으로 작성했고 컴파일하지 않았다. 특히 A01의 `CancelPendingMissiles()`는 신규 공개 함수 추가가 필요하다.
2. **N03의 3번 수정안(GE 스택 정책)** — `StackPeriodResetPolicy` 계열이 UE 5.8에서 기대대로 동작하는지 엔진 소스로 끝까지 추적하지 않았다. 채택 전 실행 확인 필요.
3. **A01의 런타임 재현** — "컴포넌트 틱이 액터 틱과 독립"이라는 엔진 동작은 코드 패턴으로 강하게 뒷받침되지만, 실제로 반납된 액터에서 미사일이 나가는 장면은 확인하지 못했다. `CRWave stop` 타이밍 재현 필요.
4. **성능 영향 미측정** — A01의 풀 액터 무기 틱 비용, R01 재생 커서 효과 모두 `CRBench` 미실행.
5. **에셋/맵 데이터** — `Content/MapData/ingame.json`, `Content/GameData/items.json`·`characters.json`은 존재와 파서 호환성만 확인했고 게임플레이 밸런스 검토는 하지 않았다.
6. **`git diff --check` 재실행 안 함** — Codex가 통과했다고 기록했으나 내가 검증하지는 않았다.
