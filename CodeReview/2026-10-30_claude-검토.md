## 성능 결과

조건은 모두 같다.
- 맵: bench 맵, 100 vs 100, 20초 측정
- 실행: 단독 실행, 1280x720, 트레이스 끔
- 장비: Ryzen 7 9800X3D, RTX 5080

| 시점 | 평균 FPS | 1% 최저 FPS | 게임 스레드 |
|---|---|---|---|
| 리뷰 전 (`a7ded15`, 2026-10-29 기록) | 86.8 | 40.4 | 11.5 ms |
| R08 포함 구현 후 (5회) | 124.2 ~ 129.6 | 51.8 ~ 59.1 | 7.7 ~ 8.1 ms |

- **R08이 대부분의 개선을 만든 것으로 판단한다.**
  - 숨겨진 무기 파츠도 손에 붙어 있으면, 손이 움직일 때마다 위치 갱신 비용이 든다.
  - 전날 트레이스에서 무기 쪽 컴포넌트 갱신이 프레임당 약 830회였다.
- 리뷰 전 수치는 전날 측정이라 같은 날 A/B는 아니다. 다만 같은 장비와 같은 조건이고, 개선 폭이 노이즈(±3 FPS)보다 훨씬 크다.
- 측정마다 `.meta.txt`에 아래 정보가 남는다(R05).
  - 커밋, 맵 해시, 진형 수치, 실제 생성 수
  - 환경, 전체 튜닝 값

## 항목별 의견

### R01 · 동의, 구현
- **확인:** 재생 성공 수만 예산을 쓰고, 대기 칸 검사는 큐 전체를 매 프레임 돌았다.
- **구현:** 커서로 큐를 이어서 돌게 했다. 프레임당 검사 수 예산(`BlockRegenVisitPerFrame`, 기본 256)은 블럭 지형 탭에 넣었다.
- **같은 칸 중복 예약:** 기존 `RegenAt` 검사가 이미 막고 있다.
- **남은 확인:** 긴 큐에서 p95/p99를 따로 재지는 않았다. 벤치마크에서 크레이터가 다시 자라는 것은 확인했다.

### R02 · 동의, 구현
- **숫자 검증:** JSON 숫자는 무한대/NaN이면 기본값을 쓰고, 정수 변환 전에 ±4096으로 자른다.
- **구조물 크기 제한:**
  - 구조물 좌표: -256~512
  - 높이: 구조물 층 수 이하
  - 두께·폭: 16 이하
  - 탑 반경: 64 이하
- **격자 교차:** fill, hole, box, 피라미드, dummy_grid는 범위를 먼저 격자와 교차시킨다. 겹치는 칸이 없으면 경고를 남기고 건너뛴다.
- **오브젝트 수:** 최대 1024개까지만 놓는다.
- **검증:** 일부러 극단적인 값을 넣은 맵을 불러왔다(fill ±100만 칸, base 1e30, radius 1e9, depth 1e12, dummy_grid ±10만 칸).
  - 해석은 즉시 끝났다. 허수아비 1024개 생성까지 포함해도 0.7초 정도였다.
  - 경고 2개가 정상적으로 남았다.
  - 기존 arena, training, bench 맵도 그대로 불러와졌다.

### R03 · 일부 동의
- **측정:** 훈련장 100 vs 100 트레이스에서 `CR_FindNearestEnemy`는 프레임당 0.008ms였다.
  - 0.2~0.4초마다 재탐색하는 지금 구조에서는 O(N²)라도 200명 규모에서 무시할 수준이다.
  - 그래서 팀별 목록과 공간 그리드는 지금 하지 않는다. 600명 이상으로 늘릴 때 다시 잰다.
- **구현:** "생성 직후 탐색이 몰린다"는 지적은 맞아서 바꿨다.
  - 첫 탐색 시점을 0~0.4초로 흩뜨렸다.
  - 표적이 없을 때도 타이머마다만 찾게 했다.
  - 표적이 죽거나 풀로 돌아가면 즉시 다시 찾는다.
- **이동 비용:** 리뷰가 말한 대로 시각 LOD는 이동·AI 비용을 줄이지 않는다. 캐릭터 이동(CharacterMovement)은 별도 과제로 남긴다(PLAN 15단계).

### R04 · 지적은 맞지만 이득이 측정되지 않아 보류
- **엔진 확인:** UE 5.8 소스를 확인했다.
  - ISM은 인스턴스가 바뀌면 `SendRenderInstanceData_Concurrent`에서 바뀐 것만 보낸다(`UpdateBounds` + `UpdatePrimitiveInstances`).
  - 따라서 이펙트, 블롭 그림자, 낙하 블럭의 `MarkRenderStateDirty`는 원리상 필요 없다.
  - 정적 블럭은 이미 이 근거로 빼 두었다.
- **실험:**
  - 위 호출을 빼고 녹화로 이펙트, 연기, 블롭 그림자가 정상인지 확인했다.
  - 같은 조건으로 2회씩 A/B를 쟀다. 새 방식은 129.6 / 124.2 FPS, 옛 방식은 127.5 / 126.3 FPS로 차이가 노이즈 안이었다.
  - 이득이 없는데 확인된 경로를 바꿀 이유가 없어서 되돌렸다.
- **다시 볼 시점:** 이펙트 수가 크게 늘거나 렌더 스레드가 병목이 되면 다시 본다.
- **파괴 블럭을 -1km로 숨기는 방식:** 경계가 커져 컬링이 약해진다. 하지만 지금 블럭 맵은 거의 항상 화면 안이라 영향이 작다. 청크 분할을 할 때 같이 정리하는 쪽에 동의한다.

### R05 · 동의, 구현 (seed는 보류)
- **조건 고정:** 시작할 때 측정·준비 시간, 트레이스, 옛 블럭 방식을 고정한다.
- **도중 변경 표시:** 시작 후 튜닝 값이 바뀌면 진행 표시와 결과에 "비교 제외" 경고를 남긴다.
  - 전투 수치는 실시간 튜닝을 읽는다. 그래서 변경을 막지 않고 표시만 한다.
  - 옵션창을 연 채 수치를 바꾸며 보는 것이 이 프로젝트의 사용법이기 때문이다.
- **메타데이터:** `.meta.txt`에 아래를 저장한다.
  - 커밋, 맵 파일 MD5, 유효 진형 수치, 측정 시작 시 실제 유닛 수
  - 빌드 구성, 에디터 여부, 해상도, CPU/GPU, 전체 튜닝 값
- **seed:** 고정하려면 전투, 재생, 이펙트 난수를 전부 명시적 스트림으로 바꿔야 해서 변경 폭이 크다. 지금은 메타에 "seed 없음, 같은 조건 3회 이상"으로 적는 것으로 갈음한다.

### R06 · 동의, 구현
- 누적 피해는 기존 `TotalDamage`로 유지한다.
- 측정 구간 기록은 옵션창 최대 구간(10초)보다 오래된 것을 지운다.
- 구간을 줄였다 늘릴 때는 최대 10초 안에서 과거 기록이 그대로 복구된다.

### R07 · 동의, 구현
- 풀이 빌려준 액터만 반납받는다(`LentActors`). 중복 반납, 풀 밖 액터, 다른 월드 액터 반납은 무시하고 경고 로그를 남긴다.
- 벤치마크와 팀 전투를 여러 번 돌린 로그에서 이 경고는 한 번도 나오지 않았다. 리뷰 말대로 지금 실제로 생기는 버그는 아니었다.

### R08 · 동의, 구현 (가장 큰 효과)
- 무기 외형은 처음 장착할 때 만든다(`BuildVisual`). 총구 섬광, 광원, 빔만 공용으로 미리 만든다.
- **트레이드오프:**
  - 풀로 재사용되는 몬스터가 다른 무기로 다시 쓰이면, 이전 무기 외형이 숨은 채로 남는다(최대 6종).
  - 벤치마크 정도에서는 문제가 없다. 장시간 무기가 섞이는 모드가 생기면, 반납할 때 안 쓰는 외형을 정리하는 정책을 추가한다.
- **확인:** 녹화로 확인한 내용은 아래와 같다.
  - 팀 전투에서 칼, 총, 미사일 발사대가 보인다.
  - 죽을 때 무기가 튕겨 나간다.
  - 플레이어 무기 전환도 정상이다.

### R09 · 방향은 동의, 시점 제안
- 캐릭터 파일(약 1500행)과 컨트롤러(약 1000행)에 서로 다른 이유로 바뀌는 코드가 섞인 것은 사실이다.
- **추천 순서:**
  1. 컨트롤러의 미리보기, 시연, 벤치마크 명령을 도구 객체로 분리한다. 게임 동작과 무관해서 위험이 가장 작다.
  2. 캐릭터의 팀 전투 AI(Chase/Battle/Patrol)를 분리한다.
  3. 시각 표현(숨쉬기, 손, LOD, 2코마)을 분리한다.
- **시점:** 인게임 모드 내용(PLAN 14단계)이 정해지면 AI 요구가 바뀐다. 그 전에 AI 구조를 굳히지 않는 편이 낫다.
- 리뷰 말대로 성능 변경과 같은 커밋에 섞지 않는다.

### R10 / D01~D07 · 일부 동의, 원본 결정이 먼저
- **같이 고칠 작은 문제:** 불꽃 HitStop/Shake가 코드 상수(0.02 / 0.4)로 남은 것은 "튜닝 수치는 레지스트리에" 규칙 위반이다. 이번에 같이 고쳤다(아래 추가 수정).
- **먼저 사용자와 정할 것:** 이 프로젝트의 튜닝 흐름은 "게임 안 옵션창에서 바꾸고 SaveGame에 저장"이다.
  - CSV/DataTable을 기본값 원본으로 들이면 원본이 둘이 된다.
  - 리뷰 문서의 우선순위 제안(데이터 기본값 → 프로젝트 override → SaveGame → 미리보기)에는 동의한다.
  - 다만 누가 CSV를 편집하는지(사람인지 AI인지), 패키징에 어떻게 포함할지를 사용자와 먼저 정해야 한다.
- **항목별 의견:**
  - **D01 블럭 표:** 동의. 위험이 작고 JSON 맵과도 잘 맞는다. 우선순위 1로 둔다.
  - **D02 무기 공통 수치:** 동의하지만 옵션창 튜닝과 원본이 겹친다. 위 결정 이후에 한다.
  - **D03 전투·벤치 프리셋:** 동의. 벤치 프리셋은 R05 메타와 함께 쓰면 재현성이 좋아진다.
  - **D04 UI 메타데이터를 DataAsset으로:** 지금은 반대한다.
    - 지금은 C++ 한 줄(`CR_TUNE`)로 추가하는 방식이고, 에셋 편집은 MCP 작업이 늘어난다.
    - 다만 미리보기와 설명을 **한국어 탭 이름으로 찾는 것**은 깨지기 쉽다는 지적에 동의한다.
    - 그래서 카테고리 ID를 따로 두는 작은 변경부터 하자는 쪽이다.
  - **D05 이펙트 색·표적 상수:** 조정 요구가 생기는 것부터 튜닝으로 옮긴다. TNT를 그렇게 처리했다. 일괄 이전에는 반대한다.
  - **D06, D07 무기·캐릭터 외형 DataAsset:** 동의. Tripo 모델 교체(CLAUDE.md 목표) 때 필요하니 그 작업과 함께 한다.
  - **config 후보:**
    - **맵 핫 리로드:** 맵 제작 모드에서만 파일을 감시하게 하자는 지적에 동의한다. 지금은 모든 모드에서 1초마다 감시한다. 작은 변경이라 다음 작업으로 둔다.
    - **이펙트 버퍼 용량:** 필요해질 때 한다.
    - **AI 탐색 정책:** R03 측정으로 불필요하다.
